## 3. 上线前必须处理的问题（Findings）

严重性说明：P1 表示在真实业务上线前必须关闭；P2 表示需要补齐契约或工程措施，存在明确的接入／交付风险。这里的“上线阻断”不意味着本地演示阶段不能继续使用。

### F1 · P1：现有工程没有完整业务服务与生产启动路径

文件清单中没有 `apps/server`、数据库迁移、`infra/compose.yaml`、生产 Compose、Dockerfile、反向代理配置或 `.env.example`。根目录命令只有前端开发、构建和测试，没有真实业务服务启动、迁移和就绪检查命令。

证据：[根目录命令](D:/work/26.10.9/all/package.json:7)、[当前运行说明](D:/work/26.10.9/all/README.md:3)。

影响：将现有工程复制到新服务器，可以尝试构建前端，但无法启动后台 API、数据库与文件服务，也无法完成两端共享数据的业务闭环。

修复要求：实现原 plan 的后端基础任务，并增加完整的生产启动、环境配置、迁移、静态网页托管、HTTPS 与反向代理部署任务。

Vite 的生产输出是 `dist`，需要部署到合适的静态托管服务；开发／本地预览命令不应作为生产服务方案。[Vite 官方部署文档](https://vite.dev/guide/static-deploy.html)

### F2 · P1：演示登录与浏览器存储不能承载正式后台

登录在浏览器中比较固定演示账号和密码，登录状态由 Session Storage 标记；业务内容和图片保存在 Local Storage。服务端没有验证账号、会话或写入权限。

证据：[登录逻辑](D:/work/26.10.9/all/apps/admin/src/views/LoginView.vue:12)、[本地数据保存](D:/work/26.10.9/all/apps/admin/src/stores/demo.ts:60)、[演示会话](D:/work/26.10.9/all/apps/admin/src/stores/demo.ts:88)。

影响：不同浏览器的数据不一致，清除浏览器存储会丢失本地内容，不能集中备份。路由守卫只是页面交互，不提供服务端访问控制。

修复要求：实施 plan 的服务端会话认证和数据库／对象存储；在发布检查中禁止将演示认证分支作为生产认证路径。真实写接口必须经过服务端认证与权限检查。

### F3 · P1：来自服务响应的新记录无法进入详情

词条与选手列表通过请求服务加载，详情页仍从 `data/demo.ts` 查找。因此实际数据库生成的新 ID 不会命中内置样本。这两条问题已通过探针复现。

证据：[词条详情](D:/work/26.10.9/all/apps/miniprogram/src/pages/word/index.ts:1)、[选手详情](D:/work/26.10.9/all/apps/miniprogram/src/pages/candidate/index.ts:1)。

修复要求：明确词条和选手详情的接口／数据获取策略，让详情使用同一后端数据来源；为不存在、下架及请求失败分别处理状态。增加“后台新增记录 → 列表出现 → 点击详情 → 字段一致”的真实联调测试，不只使用 `w1`、`c1` 等样本 ID。

### F4 · P2：plan 与实现之间存在接口契约漂移

- plan 的 `HomeConfig`、首页读写接口没有 `subtitle`；管理网页已经编辑该字段，小程序也将其声明为必填。
- plan 定义了通用分页响应，但新增 `/api/public/learning` 和 `/api/public/voting` 使用聚合结构，没有在原 plan 中定义这些接口及分页例外。
- 后台题目模型只有文本 `answer`，小程序模型需要 `answers[]` 和 `options[]`，图片选项还需要图片地址。读模型（Read Model）和写模型（Write Model）可以不同，但目前没有定义转换关系，后台也不能维护完整的选择题选项。

证据：[原 plan 接口表](D:/work/26.10.9/docs/2026-10-09-wechat-platform-plan.md:149)、[小程序内容 DTO](D:/work/26.10.9/all/apps/miniprogram/src/services/content.ts:3)、[后台题目模型](D:/work/26.10.9/all/apps/admin/src/data/seed.ts:8)、[小程序题目模型](D:/work/26.10.9/all/apps/miniprogram/src/data/demo.ts:8)。

修复要求：建立唯一的机器可校验接口契约（API Contract），明确路径、方法、字段、必填／可空、分页、错误、鉴权和媒体 URL 规则。Mock 响应、前端类型和后端验证使用同一来源；明确模型转换，而不是要求所有读写结构机械相同。

小程序与浏览器的传输方式不同，共享契约不代表直接共用依赖浏览器 API 的 SDK；生成的类型／调用适配层应分别通过各自构建检查。

### F5 · P2：内部响应数据没有运行时校验

请求封装检查了 `{data:...}` 和错误包装，然后直接用 `as T` 返回。TypeScript 类型断言不会验证运行中的响应；例如数字 `title` 进入页面后才产生 TypeError，错误文字还会直接出现在加载失败状态中。

证据：[请求封装](D:/work/26.10.9/all/apps/miniprogram/src/domain/request-client.ts:78)、[内容服务](D:/work/26.10.9/all/apps/miniprogram/src/services/content.ts:17)，以及探针结果。

修复要求：在接口边界按契约验证 DTO；将缺失字段、非法类型和非法媒体地址转为稳定、可展示的错误码和文案。契约测试应覆盖空列表、缺字段、非法类型和错误响应，不只验证最外层包装。

### F6 · P1：原 plan 缺少新服务器上线验收门槛

plan 已有健康检查、数据库迁移、原子限额、会话与配置闭环设计，这些应保留。但它没有把目标服务器环境、完整生产部署包、首次启动依赖顺序、生产配置注入、数据库／对象存储恢复和版本回滚列为必须通过的验收项。

修复要求：在 plan 中增加独立“上线与新服务器验收”阶段。不能把“部署技术栈已列出”或“本机命令通过”当作新服务器可运行的证据。

## 4. 必须补入 plan 的实施与验收项（Required Additions）

### 阶段 A：封闭接口契约与接入缺口

1. 明确现阶段全部接口，包括首页、媒体、题目、词条、课程、活动、选手和对应详情；资料未到位时用合成数据（Synthetic Data）验证已确定的结构。
2. 建立唯一契约与两端类型生成／校验流程，明确版本变更方式。首页 `subtitle`、列表聚合／分页和媒体 URL 先达成一致。
3. 修复 F3，补充列表到详情、后台写入到小程序读取的测试。
4. 完成真实管理员认证、数据库与图片存储；关闭生产构建中的演示认证和默认 Mock 分支。小程序的 API 地址与环境应进入明确的构建／发布配置流程，不能依赖服务器运行时环境变量自动改写已发布小程序。

### 阶段 B：建立生产部署包（Production Deployment Package）

1. 先锁定目标操作系统、CPU 架构、运行时与资源要求；可选择 Linux/amd64 作为首个验收目标，其他架构另行验证。本次尚未证实这个目标能运行。
2. 提供管理员静态网页托管、API 服务、PostgreSQL 与对象存储的部署文件；锁定对应镜像和工具版本，排除临时缓存、审计快照和个人开发配置。
3. 提供 `.env.example` 与逐项说明；缺少密钥、数据库地址、存储配置时必须启动失败并给出明确诊断。真实密钥不得打包进网页或小程序。
4. 首次启动按“数据库／存储就绪 → 数据库迁移 → 桶初始化与管理员初始化 → API 就绪 → 网页与代理可访问”执行；初始化应可安全重跑。
5. 配置 HTTPS、公开图片地址、同源 `/api` 代理、可信代理 IP、健康检查与进程重启策略。

Compose 的容器“运行中”不等于数据库已就绪；应使用健康检查和 `service_healthy`，必要时对迁移任务使用 `service_completed_successfully`。[Docker 官方启动顺序说明](https://docs.docker.com/compose/how-tos/startup-order/)

Prisma 尚未在工程中安装或锁定版本；选择版本后必须确定该版本对应的生产迁移命令、执行时机与安全重跑方式，不能只给脚本起名 `db:migrate`。[Prisma 官方迁移说明](https://www.prisma.io/docs/orm/migrations/applying-a-migration)

### 阶段 C：全新服务器验收（Fresh-server Acceptance）

以下验收应在无历史数据库、无现成 `node_modules`、无预建 `dist`、无旧镜像依赖的目标环境执行，并保存命令、版本、退出码和接口响应证据：

- [ ] 从部署包和必要配置完成安装／启动，不手工复制开发机生成的隐藏配置。
- [ ] 空数据库迁移成功；再次运行迁移不重置业务数据。
- [ ] 缺少配置时启动明确失败；依赖未就绪时不误报 ready。
- [ ] 正确登录可用，错误密码被拒绝，过期／撤销会话不可写入，未登录写接口返回 `401`。
- [ ] 后台保存首页标题、介绍与图片后，小程序读取一致；不同浏览器看到同一份正式数据。
- [ ] 新增非样本 ID 的词条和选手，列表与详情均正确；不存在的 ID 得到约定的错误／空状态。
- [ ] 图片对外可访问，地址不含容器内部主机名、开发机盘符或 `localhost`。
- [ ] 服务和主机重启后数据、图片和必要配置保留。
- [ ] 数据库和对象存储完成一次备份／恢复演练；恢复结果可由 API 与页面核对。
- [ ] 完成一次版本升级与回退演练，明确数据库变更的兼容范围；代码回退不默认等于数据库可逆。
- [ ] 用真实 HTTP 和反向代理验证 IP 限额、并发请求、失败回滚及北京时间 04:00 边界。
- [ ] 使用可用 AppID、正式配置的服务地址完成微信原生编译与真机流程验证；不能以 VM 页面测试代替。
- [ ] 发布流程拒绝带演示认证／未确认 Mock 模式的业务版本。

## 5. 建议执行顺序（Recommended Sequence）

**先修接口契约和详情链路，再实现真实认证／保存闭环，然后完成生产部署与全新服务器验收。** 这些基础工作大多可以用合成数据开展，不需要等待全部甲方题库和图片。

本次只新增审计报告、临时快照与探针，未修订原 plan 的正文，也未修改业务源代码。结论应作为下一轮修订 plan 和验收标准的依据；不能据此标记生产验收通过。
